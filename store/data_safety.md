# Data safety — готовые ответы для p2pchat

Принцип: **Collected** = данные получает разработчик (наш сервер жалоб); **Shared** = данные уходят другим пользователям или третьим лицам (KLIPY). Локальное хранение на устройстве само по себе не считается сбором.

## Верхние вопросы

| Вопрос | Ответ |
|---|---|
| Собирает/передаёт ли приложение пользовательские данные? | **Да** |
| Все данные передаются в зашифрованном виде? | **Да** (TLS + MLS E2E) |
| Способы создания аккаунта | **В приложении нельзя создать аккаунт** (`PSL_ACM_NONE`) |
| Внешние аккаунты (SIM, компания и т.п.) | **Нет** |
| Удаление данных пользователем | **Да** |
| URL удаления данных | `https://dabuldakov.github.io/p2p-chat/data-deletion.html` |
| URL удаления аккаунта | тот же (аккаунтов нет) |
| Family policy | **Нет** |
| MASA / независимая проверка | **Нет** |
| UPI badge | **Нет** |

## Типы данных

| Категория Play | Тип | Collected | Shared | Обязательность | Назначение |
|---|---|---|---|---|---|
| Личная информация | Имя (ник) | Нет | **Да** (участникам групп) | Пользователь может не указывать | Функции приложения |
| Личная информация | Идентификаторы пользователей (peer_id / публичный ключ) | **Да** (в жалобах) | **Да** (участникам групп) | Обязательно (peer_id) | Функции приложения; предотвращение мошенничества и безопасность |
| Фото и видео | Фотографии (аватар, скриншот жалобы) | **Да** (скриншот жалобы) | **Да** (аватар участникам) | Пользователь может не указывать | Функции приложения; предотвращение мошенничества и безопасность |
| Сообщения | Другие сообщения в приложениях | Нет | **Да** (участникам групп) | Пользователь выбирает, что отправлять | Функции приложения |
| История действий | История поиска в приложении (GIF-запросы) | Нет | **Да** (KLIPY) | Только при поиске | Функции приложения |
| История действий | Другой контент, созданный пользователями (комментарий в жалобе) | **Да** (жалоба) | Нет | Пользователь выбирает | Функции приложения; предотвращение мошенничества и безопасность |

**Не отмечаем:** местоположение, контакты, календарь, здоровье/фитнес, финансы, SMS/звонки, email, аудио, видео, файлы, история браузера, установленные приложения, crash logs, diagnostics, рекламные/device ID.

## Пояснения для ревьюера (если спросят)

- Сообщения **E2E (MLS)**, на сервере не хранятся; signaling/TURN видят только метаданные соединения (IP, SDP/ICE) и не могут расшифровать содержимое. В Play-сборке GitHub-обновлятор отключён (`PLAY_BUILD=true`).
- Жалобы: на сервер уходят публичный ключ отправителя, peer_id нарушителя, ID группы/сообщения, причина, комментарий, скриншот (по желанию), время и IP. Хранятся до 90 дней, только для модерации/безопасности.
- GIF-поиск: запрос уходит в KLIPY (api.klipy.com), их политика применяется.
- Удаление: сообщения/группы/данные приложения — на устройстве; жалобы — по письму на dabuldakov@gmail.com или автоматически через 90 дней; сообщения на чужих устройствах удалить нельзя.
- Медиа из сообщений (фото/видео/аудио/голос/видеосообщения): файлы хранятся на устройствах и передаются участникам группы P2P; на сервер не загружаются.
- Смена владельца группы: роль владельца, heartbeat, заявки и голоса хранятся локально и передаются участникам группы как подписанные служебные события. На сервер они не уходят; отдельный тип Data safety не нужен (идентификаторы пользователей уже отмечены).

## CSV-экспорт

В `data_safety_export.csv` колонка `Response value` пустая. Если Play Console позволяет импорт, для выбранных `Response ID` ставьте `TRUE`, для остальных оставьте пусто; для свободных полей (`PSL_DATA_DELETION_URL`, `PSL_ACCOUNT_DELETION_URL`) впишите URL выше. Если импорт не поддерживается — заполняйте по таблицам выше.
