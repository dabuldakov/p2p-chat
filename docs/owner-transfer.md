# Передача владения группой (owner transfer)

Статус: **реализовано** (heartbeat, заявки/голоса/кворум, вызов, авто-претендент,
заморозка состава, персист, офлайн-replay, уведомления, UI, 15 языков).
Дата: 2026-10-24.

## Цель

Если владелец группы исчез (потерял телефон, удалил приложение, не заходит), группа не должна
навсегда остаться без управления. Участники могут выбрать нового владельца — прозрачно,
детерминированно и без центрального сервера.

Владелец — это **локальная роль** (`owner:<gid>`), а не часть MLS. Передача должна быть
подписана участниками и сойтись у всех.

## Параметры

| Параметр | Значение |
|---|---|
| Отсутствие владельца (N) | **7 дней** |
| Heartbeat владельца | **12 часов** (и любое событие владельца считается активностью) |
| Окно заявок | **24 часа** |
| Голосование | **24 часа** |
| Кворум | **строго >50% участников без владельца** |
| Подтверждение авто-претендента | **24 часа**, возражения >50% отменяют |
| Cooldown после неудачи | **3 дня** |
| Порядок наследников | сортировка участников без владельца по `peer_id` |
| «Активный» наследник | локально учитывается last_seen ≤ 14 дней; заявитель доказывает активность отправкой |
| Минимум для передачи | 2 участника (владелец + 1); если владелец один — передачи нет |

## Состояния

```
OWNER_ACTIVE
  └─ нет активности владельца 7 дней ─► ABSENT
ABSENT (окно заявок 24 ч, состав заморожен)
  ├─ есть заявки ─► VOTING (24 ч)
  ├─ нет заявок  ─► CONFIRMING (авто-претендент, 24 ч)
  └─ владелец вернулся ─► OWNER_ACTIVE (отмена)
VOTING
  ├─ кворум + большинство ─► OWNER_CHANGED
  ├─ кворум не набран/все против ─► FAILED → COOLDOWN (3 дня)
  └─ владелец вернулся ─► OWNER_ACTIVE (отмена)
CONFIRMING
  ├─ возражений ≤50% ─► OWNER_CHANGED
  ├─ возражений >50% ─► FAILED → COOLDOWN (3 дня)
  └─ владелец вернулся ─► OWNER_ACTIVE (отмена)
OWNER_CHANGED
  └─ new_owner получает права: приглашения, удаление, имя, аватар
```

## Кто может

- **Заявка**: любой текущий участник, кроме владельца, один раз; в одном окне может быть
  несколько заявок. Заявка = голос за себя.
- **Голос**: любой текущий участник, кроме владельца (для absent/auto) и заявителя; один голос.
- **Авто-претендент**: первый по `peer_id` не-владелец, активный последние 14 дней
  (по локальной таблице peers). Если активных нет — авто-претендента нет.
- **Состав заморожен** на всё время ABSENT/VOTING/CONFIRMING: новых участников не добавляем
  (защита от накрутки голосов). Инвайты и так только у владельца.

## Добровольный вызов владельца (weekly challenge)

Кроме «владелец исчез», участники могут **сами** инициировать смену владельца — как вотум
доверия, без ожидания 7 дней.

- **Триггер**: любой участник, кроме владельца, не чаще **1 раза в 7 дней на группу**
  (cooldown после любого вызова).
- **Заявки**: 24 ч (может заявиться любой участник, включая владельца — «остаться»).
- **Голосование**: 24 ч, участвуют **все текущие участники, включая владельца**.
- **Кворум**: **>50% всех участников**. В группе из 2 человек нужны оба голоса, поэтому один
  участник не может забрать владение без согласия владельца.
- Владелец — вариант «оставить владение» по умолчанию. Побеждает кандидат, набравший >50%
  всех голосов; иначе владелец остаётся.
- Если заявок нет — ничего не происходит (владелец остаётся).
- Те же события (`OwnerClaim`/`OwnerVote`/`OwnerChange`), но с `trigger = challenge`
  (в отличие от `trigger = absent`).
- Состав заморожен на время вызова; cooldown 7 дней после завершения (успех/провал).
- UI: в меню группы «Оспорить владение» (доступно раз в 7 дней); у владельца — «Оставить
  владение»; уведомления и системные сообщения.

## События (proto-эскиз)

```
OwnerAlive  { group_id, owner, at }                       // в подписанном Envelope
OwnerClaim  { group_id, claim_id, claimant, claimant_key, trigger,
              last_seen_owner, created_at, nonce, sig }
OwnerVote   { group_id, claim_id, voter, voter_key, approve, keep, at, sig }
OwnerChange { group_id, claim, votes[], new_owner, at, epoch, candidates[] }
```

- `claim_id` = хэш содержимого claim.
- Подписи Ed25519 ключами участников; проверка членства на текущей MLS-эпохе.
- `OwnerChange` содержит подписи достигших кворума голосов; каждый клиент проверяет их сам.

## Правила приёма

- Только от участников группы; подпись сходится с ключом участника.
- Несколько заявок в одном окне; один голос на участника; заявитель голосует за себя неявно.
  Конфликт двух `OwnerChange` с одинаковым epoch разрешается детерминированно: больше
  голосов → порядок наследников → `peer_id`/`claim_id`.
- `last_seen_owner` в claim должен быть ≥ 7 дней назад (по часам заявителя); голосующий
  дополнительно проверяет по своему `last_seen` — если недавно видел владельца, голосует против.
- Таймстемпы с допуском (например, ±10 минут); claim истекает по дедлайну.
- Владелец вернулся (любое `OwnerAlive`/событие) до финализации → claim отменяется.
- Кворум считается по **текущему** составу без владельца; при изменении состава — пересчёт.
- Ничьи: порядок наследников → меньший `peer_id` (для одной заявки неактуально).
- Partition/два claim: побеждает `OwnerChange` с большей epoch; при равной — детерминированный
  ранг. Один владелец.

## Безопасность

- **Заморозка состава** на время процесса — против sybil/накрутки.
- **Только владелец** может инициировать MLS Add/Remove/переименование/аватар. Клиенты
  проверяют отправителя коммита и игнорируют чужие изменения состава. (MLS технически
  позволяет коммит любому участнику — это ограничение на уровне приложения.)
- **Старый владелец не возвращает владение автоматически** после передачи (защита от
  украденного старого устройства). Возврат — только новым claim/решением текущего владельца.
- **Seed-recovery**: вернувшийся с тем же ключом до финализации отменяет процесс; после
  передачи — обычный участник. Если seed утерян — работает только выборы.
- Rate limit на claim/vote; nonce/claim_id против replay.
- Приватность: голоса — обычные служебные события группы, не публикуются наружу.

## UX

- **T0+7 дней**: иконка (янтарный щит) в шапке группы + одно уведомление. Тап → диалог
  «Владелец неактивен 7 дней».
- Диалог/состояния:
  1. Нет заявок: «Заявить права» (для всех, кроме владельца), таймер 24 ч.
  2. Есть заявки: список, «Голосовать», прогресс кворума, таймер 24 ч.
  3. Нет заявок 24 ч: «Авто-претендент: <X>», таймер подтверждения 24 ч, «Возразить».
  4. Возражения: переход в голосование.
  5. Успех: «Владелец: X», системное сообщение в чат, у нового владельца появляются кнопки.
  6. Неудача: сообщение, иконка скрыта на 3 дня.
  7. Возврат владельца: всё отменяется, иконка исчезает.
- Уведомления: старт процесса и необходимость голоса.
- i18n: все строки в 15 языках.

## Персист и синк

- Хранить: `last_seen_owner`, активный claim, голоса, результат, cooldown.
- Финальный `OwnerChange` и `OwnerPolicy` — в meta; синкать офлайн-участникам при онлайне.
- Pending claim/голоса — с TTL; после рестарта не терять финальное состояние.
- Офлайн-участник, вернувшись, получает актуального владельца, а не старого.

## Крайние случаи

- 2 участника: второй — и заявитель, и кворум.
- Наследник офлайн/пропал → следующий; если активных нет — ждём заявок.
- Состав изменился во время голосования → пересчёт кворума; при заморозке не меняется.
- Старые группы без owner-меты → владелец из meta/fallback, порядок по `peer_id`.
- Владелец — единственный участник → передачи нет.
- Владелец активен, но не шлёт heartbeat → считается активным по любому событию; иначе 7 дней.
- Часы участников расходятся → допуск и локальные проверки `last_seen`.
- Два устройства с одним seed → дубли identity/leaf; вне scope (multi-device — отдельно).

## Тесты

- Отсутствие 7 дней → заявка → кворум → смена владельца.
- Вызов: 3 из 4 — смена; без большинства — владелец остаётся.
- Авто-преемник после окна заявок; без голосов; возражения >50%; пропуск неактивного.
- Несколько заявок — побеждает относительное большинство.
- Возврат владельца отменяет выборы; отклонение + cooldown 3 дня.
- Активные выборы переживают перезапуск; офлайн-участник получает `OwnerChange`.
- Чужой MLS Commit отклоняется без merge.

## Что реализовано

- `OwnerAlive`, 7 дней отсутствия, 12-часовой heartbeat, баннер «владелец неактивен».
- `OwnerClaim`/`OwnerVote`/`OwnerChange`, несколько заявок, кворум >50%, reject-голоса,
  24 ч заявок + 24 ч голосования; auto — 24 ч подтверждения с возражениями >50%.
- Триггеры: отсутствие, добровольный вызов, авто-преемник (минимальный активный `peer_id`).
- Возврат владельца до финализации отменяет выборы; после смены старый владелец —
  обычный участник. Старый владелец не возвращает роль автоматически.
- Cooldown: 3 дня после провала отсутствия/авто, 7 дней между вызовами.
- Заморозка состава: инвайты и удаление участников блокируются; выйти самому можно.
- Персист: активные заявки/голоса — `owner_election:<gid>`, итог — `owner`,
  `owner_epoch`, `owner_change`; активные выборы переживают перезапуск.
- Офлайн-replay: последний `OwnerChange` пересылается при подключении пира и раз в минуту;
  опоздавший участник догоняет владельца без повторных выборов.
- Коммиты MLS (Add/Remove/Update) принимаются только от текущего владельца до merge.
- Уведомления: старт выборов и «нужен ваш голос»; отдельный канал, без бейджа.
- Системный баннер в группе при смене владельца (в т.ч. после выхода владельца).
- UI: карточка выборов, список заявок, «за/против», «оставить владельца»,
  «Запросить владение»/«Оспорить владельца». Строки — 15 языков.
- Тесты: отсутствие, вызов с большинством/без, авто без голосов и с возражениями,
  активный/неактивный наследник, несколько заявок, возврат владельца, cooldown,
  персист, офлайн-replay, owner-only MLS commit.

## Ограничения

- Пока инвайты только у владельца: во время его отсутствия новые участники не появляются
  (это же защищает выборы от накрутки).
- Роль владельца не криптографическая в MLS; строгость обеспечивается клиентами.
- При partition возможны временные конфликты MLS-эпох; после слияния — детерминированный
  выбор владельца и повторный синк.
